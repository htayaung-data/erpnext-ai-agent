This roadmap exists to stop implementation from drifting after research.

1. the original Phase `3.3` design notes
2. the enterprise evaluation note
3. three completed research rounds
4. a dedicated ambiguity-handling evaluation

The project now needs one clear answer to:

1. what is already finished
2. what is still open in current Phase `3.3`
3. what is explicitly deferred to later governed scope expansion
4. what order implementation should follow from here

This roadmap is that answer.

1. close the remaining bounded current Phase `3.3` alignment work

3. start the next governed scope expansion chapter
4. expand ambiguity handling only through the existing typed clarification system, in the later expansion chapter, not as isolated phrase fixes now

Important boundary:

The three research rounds are complete.

## 4. What Research Has Now Established

The completed research program gives us these stable conclusions.

### 4.1 Current Strong Assets

The system already has:

1. strong governed ranking and projection contracts
2. strong customer direct-lookup reference behavior
3. real entity drilldown lane
4. real clarification and evidence-boundary architecture
5. real typed entity-reference resolution contrac
6. strong follow-up boundary and continuity system

### 4.2 Current Confirmed Open Gaps

Research proved these are still open:

1. purchase-invoice generic routing is misaligned
2. supplier direct navigation is not policy-active
3. item/product direct navigation is not policy-active
4. payment entry is partial and still lacks clear generic family ownership
5. ambiguity handling exists but is still narrow in activation breadth
6. entity-detail execution still contains mixed branch-driven authority

### 4.3 Most Important Sequencing Conclusion

The project should not mix:

1. current Phase `3.3` closure work
2. later governed scope expansion
3. later broad ambiguity expansion

Those must be separated explicitly.

## 5. Current Phase Status After Research

### 5.1 Phase `3.3`

Research conclusion:

1. Phase `3.3` should not be treated as automatically closed ye
2. but it also should not be widened into broader supplier/item/payment-entry expansion

So the current Phase `3.3` status is:

1. research-complete
2. implementation-order now clarified
3. bounded closure work still allowed

### 5.2 Next Expansion Chapter

The next governed scope expansion chapter should begin only after `3.3` closure is explicit.

That later chapter will own:

1. supplier direct navigation
2. item/product direct navigation
3. payment-entry ownership and activation
4. broader typed ambiguity expansion

2. reuse current clarification lane

4. expand by approved family, not by phrase
